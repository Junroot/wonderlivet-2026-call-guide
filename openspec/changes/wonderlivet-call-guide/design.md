## Context

- 저장소는 빈 상태이고, 탐색 세션의 조사 결과만 `research/`에 있다.
  - `research/final-songs.md`: 최종 곡 목록 56곡과 근거
  - `research/research-*.md`: 아티스트별 응원 자료 출처
  - `research/setlist-*.md`: 셋리스트 연주 빈도
  - `research/extra-calls-*.md`: 추가 조사 결과
- 사용자 결정 사항
  - 개인 연습용이다.
  - 응원 정보가 있는 곡만 넣는다.
  - 타이밍 기능이 필수다.
  - 가사 원문과 한글 발음을 넣는다. 번역은 넣지 않는다.
  - GitHub Pages로 공개 배포한다. 가사 공개 위험은 사용자가 감수한다.
- 기존 응원 자료 중 타임스탬프가 있는 것은 없다. 모든 자료가 "2절 후렴", "이 가사 다음" 같은 곡 구간·가사 위치 기준이다.
- LRCLIB에서 시험 검색한 4곡(狂乱 Hey Kids!!, ワタリドリ, 고민중독, 倍倍FIGHT!)에는 모두 줄 단위 동기화 가사가 있었다.
- 일정: 오늘이 2026-11-10이고 공연은 11-20이다. 늦어도 11-17에는 1차 배포가 나가야 한다.
- 콘텐츠의 최종 검수자는 사용자다. Claude는 소리를 들을 수 없으므로 타이밍과 발음은 초안까지만 만든다.

## Goals / Non-Goals

**Goals:**
- 빌드 과정 없이 GitHub Pages에 그대로 올라가는 정적 사이트를 만든다.
- YouTube 재생 시간에 맞춰 현재 가사 줄과 콜을 강조하는 연습 화면을 만든다.
- 콜을 가사 줄에 붙여 두면 시간이 자동으로 정해지게 한다. 가사가 없는 구간의 콜만 시간을 직접 찍는다.
- 사용자가 곡당 몇 분 안에 타이밍을 검수할 수 있는 보정 도구를 만든다.
- 곡 데이터를 파일 단위로 추가할 수 있게 한다. 재조사로 곡이 늘어나도 코드는 바뀌지 않아야 한다.

**Non-Goals:**
- 공연장 현장 사용은 고려하지 않는다. 오프라인 캐시와 PWA는 넣지 않는다.
- 팀별 공유 미리보기(OG 태그), 기여 받기, 출처 크레딧 정책은 다루지 않는다. 공개 공유 용도가 아니기 때문이다.
- 가사 번역은 넣지 않는다.
- 응원 정보가 없는 19팀(Da-iCE 포함 20팀)의 페이지는 만들지 않는다.
- 음원을 직접 호스팅하지 않는다.

## Decisions

### 1. 빌드 없는 바닐라 HTML + ES 모듈 + JSON

`index.html` 하나가 ES 모듈 스크립트를 불러오고, 화면은 해시 라우팅(`#/`, `#/artist/<id>`, `#/song/<id>`)으로 전환한다.

- **Astro를 쓰지 않는 이유:** 정적 페이지를 미리 생성해서 얻는 이점은 팀별 OG 미리보기뿐이었다. 개인 용도로 바뀌면서 그 이점이 사라졌다.
- **해시 라우팅을 쓰는 이유:** GitHub Pages는 서버 측 라우팅을 지원하지 않는다. 경로 라우팅을 쓰면 404.html 우회 처리가 필요한데, 해시 라우팅은 그런 처리가 필요 없다.
- **프레임워크를 쓰지 않는 이유:** 화면이 세 종류(목록, 연습, 보정)뿐이라 DOM을 직접 다뤄도 감당할 만하다. 의존성도 없앨 수 있다.

### 2. 데이터 구조: 라인업 파일 하나와 곡별 파일

```
data/
├─ lineup.json            # 22팀: id, 이름(원문·한글), 일자, 스테이지, 시간, 공연 의식
├─ songs/index.json       # 곡 파일 목록 (검증 스크립트가 생성)
└─ songs/<artist-id>/<song-id>.json
```

정적 호스팅에서는 디렉터리 목록을 읽을 수 없다. 그래서 `songs/index.json`을 검증 스크립트가 생성하게 한다.

곡 파일의 핵심 필드는 다음과 같다.

| 필드 | 내용 |
|---|---|
| `youtube.videoId`, `youtube.offsetSec` | 재생할 영상과 시간 보정값 (영상 시간 = 가사 시간 + offset) |
| `lrclib.id`, `durationSec` | 가사 출처와 음원 길이 |
| `lines[]` | `{ t, text, ko }` (`t`는 초 단위, `ko`는 한글 발음이며 한국어 곡은 null) |
| `cues[]` | `{ type, text, ko, note, color, at }` |
| `sources[]` | 응원 정보 출처 `{ label, url }` |
| `review` | `{ pronunciation: bool, timing: bool }` 검수 완료 여부 |

`cues[].at`은 세 가지 형식 중 하나다.

- `{ line: 12, offset: 0.4 }`: `lines[12]`(0부터 세는 첨자, 즉 13번째 가사 줄)의 시간에 0.4초를 더한다. 대부분의 콜이 이 형식이다.
- `{ t: 83.2 }`: 절대 시간이다. 간주 박수나 인트로 점프처럼 가사가 없는 구간에 쓴다.
- `{ t: null }`: 시간 미정 절대 시간 콜이다. Claude는 소리를 들을 수 없으므로 절대 시간 콜의 초안은 이 형식으로 적고, 사용자가 보정 도구로 시간을 찍는다.

**`at.line`을 0 기준 첨자로 정한 이유:** 계산식 `lines[line].t + offset`과 코드의 배열 첨자가 그대로 일치해, 변환 과정에서 한 줄씩 밀리는 실수를 막는다. 콘텐츠를 입력할 때는 원자료의 "N번째 줄"을 그대로 적지 말고 `N - 1`로 적어야 한다. 한 줄씩 밀린 값은 형식상 유효해서 검증 스크립트로 잡히지 않기 때문이다.

시간을 계산할 수 없는 콜(`{ t: null }`, 또는 `t`가 null인 줄에 붙은 줄 기준 콜)은 연습 화면에서 "다음"·"지금" 강조 없이 콜 목록에만 표시한다.

콜 종류(`type`)는 `call`(외치기), `clap`(박수), `jump`(점프), `singalong`(떼창), `motion`(손동작·안무), `penlight`(펜라이트 색), `other`로 고정한다. 탐색 세션에서 확인한 다섯 가지 응원 유형(아이돌 콜, 밴드 구호, 클랩·점프, 떼창, 감상)이 모두 이 종류들로 표현된다. 감상형 팀은 이번 범위에서 빠졌다.

**가사 줄 기준 형식을 기본으로 정한 이유:** 기존 자료가 모두 가사 위치 기준이라 받아 적기 쉽다. 또 오프셋이 바뀌거나 가사 시간을 보정해도 콜 시간이 함께 따라간다.

### 3. 가사 타이밍은 LRCLIB, 영상은 공식 음원 우선

- 콘텐츠 준비 단계에서 LRCLIB API로 동기화 가사를 받아 `lines[].t`와 `text`를 채운다. 사이트가 실행될 때는 LRCLIB를 호출하지 않는다.
- 영상은 YouTube의 "Provided to YouTube" 공식 음원(Topic 채널)을 먼저 고른다. 없을 때만 공식 MV를 쓴다. MV는 앞에 인트로 영상이 붙는 경우가 많아 `offsetSec`가 필요하다.
- 보정 화면이 영상 길이를 `youtube.durationSec`에 기록한다. 검증 스크립트는 이 값과 `durationSec + offsetSec`의 차이가 2초를 넘으면 경고를 띄운다. 오프라인 스크립트는 YouTube 영상 길이를 직접 알 수 없기 때문이다.
- **라이브 영상을 쓰지 않는 이유:** 라이브 영상은 편곡과 템포가 공연마다 달라 LRCLIB 타이밍과 맞지 않는다. 대신 라이브에서만 하는 의식(오랄의 「4本打ち」, 삼보마스터의 「全員優勝!」 등)은 `lineup.json`의 아티스트별 공연 의식 항목으로 분리한다.

### 4. 재생 동기화: YouTube IFrame API와 보간

- `player.getCurrentTime()`은 iframe 메시지로 갱신되는 값이라, 갱신 간격이 수백 ms일 수 있다.
- 그래서 마지막으로 받은 값과 그 시각의 `performance.now()`를 기억해 두고, `requestAnimationFrame` 루프에서 `값 + 경과 시간 × 재생 속도`로 보간한다.
- 콜은 1.5초 전에 "다음" 상태로 미리 보여주고, 해당 시간에 강조한다. 박자를 맞춰 준비할 시간이 필요하기 때문이다.
- 연습 기능은 최소한으로 넣는다.
  - 가사 줄을 누르면 그 위치로 이동한다.
  - 재생 속도를 0.75배와 1배 중에서 고를 수 있다.
  - 한글 발음 표시를 켜고 끌 수 있다.

### 5. 타이밍 보정 도구: 같은 사이트 안의 `#/edit/<song-id>`

- 곡 JSON을 불러와 영상을 재생한다.
  - Space를 누르면 "다음 대상"에 현재 가사 시간(`영상 시간 - offsetSec`)을 기록한다. 다음 대상은 목록 순서상 다음 중 첫 항목이다.
    - 시간이 없는 가사 줄: `t`를 기록한다.
    - 시간 미정 절대 시간 콜(`{ t: null }`): `t`를 기록한다.
    - 이번 보정 작업에서 아직 기록하지 않은 줄 기준 콜: `offset = 현재 가사 시간 - lines[line].t`를 기록한다. Claude 초안의 `offset`은 눈대중이라 모두 귀로 확인해야 하기 때문이다. 목록에서 줄 기준 콜은 자신이 붙은 줄 바로 뒤에 오므로, 줄 시간이 정해진 뒤에야 대상이 된다. 기록 여부는 작업 상태(`localStorage`)에만 두고 곡 JSON에 필드를 추가하지 않는다.
  - ←/→는 선택한 항목을 ±0.1초 조정한다. 가사 줄과 절대 시간 콜은 `t`를, 줄 기준 콜은 `offset`을 조정한다.
  - 숫자키는 재생 속도를 바꾼다.
- 결과는 JSON 파일로 내려받거나 클립보드에 복사한다. 사용자는 받은 파일을 `data/songs/`에 덮어쓰고 커밋한다.
- 작업 중 상태는 `localStorage`에 임시 저장한다. 실수로 새로고침해도 기록이 남게 하려는 것이다. 저장소에 반영되는 것은 내보낸 JSON뿐이다.
- **별도 앱으로 만들지 않는 이유:** 재생 동기화 코드를 연습 화면과 공유할 수 있다. 공개 사이트에 보정 도구가 함께 있어도 저장소에 쓰는 기능이 없으니 해가 없다.

### 6. 한글 발음은 Claude 초안, 사용자 검수

- 일본어 가사 줄마다 Claude가 한글 발음 초안을 `ko`에 채운다. 장음은 `-`로 표기하고(예: `쿄-란`), 영어 구절은 원문을 그대로 둔다.
- `review.pronunciation`이 false인 곡은 화면에 "발음 검수 전" 표시를 띄운다.
- 한자 읽기가 틀릴 수 있으므로 초안 단계에서는 후리가나가 있는 출처(가사 사이트)를 참고한다.

### 7. 콘텐츠 준비 도구는 의존성 없는 Node 스크립트

- `tools/fetch-lrclib.mjs <artist> <title> [duration]`: LRCLIB에서 동기화 가사를 검색해 곡 JSON 뼈대를 만든다.
- `tools/validate.mjs`: 다음 항목을 검사하고 `songs/index.json`을 생성한다.
  - 모든 곡 JSON의 필수 필드
  - 콜 종류
  - 가사 줄 참조 범위
  - 시간 단조 증가
  - 길이 차이
  - 시간이 없는 콜(`{ t: null }`)은 오류가 아닌 경고로 처리한다. 초안 상태로 색인 생성과 배포(tasks 7.3 등)를 막지 않기 위해서다.
- 사이트 자체에는 빌드가 없다. Node는 콘텐츠를 준비할 때만 쓴다.
- **Python이 아닌 Node를 쓰는 이유:** 사이트 코드와 같은 언어라, 검증 로직(콜 시간 계산 등)을 사이트 모듈과 공유할 수 있다.

### 8. 배포: GitHub Pages, main 브랜치 루트

- Pages 설정을 "Deploy from a branch"의 `main` / `(root)`로 둔다. Actions 워크플로는 쓰지 않는다.
- `.nojekyll`을 넣어 Jekyll 처리를 끈다.
- 저장소는 공개 저장소로 둔다. 무료 Pages의 조건이다.

### 9. 임베드 차단 곡: 외부 재생 + 사이트 자체 시계

임베드가 막힌 곡은 사용자가 YouTube 앱이나 다른 탭에서 곡을 틀고, 사이트는 자체 시계로 가사·콜을 진행한다.

- 플레이어가 오류 101/150을 보고하거나 `videoId`가 없으면 외부 재생 모드로 바꾼다. 영상이 재생되는 곡에서도 사용자가 이 모드를 고를 수 있다(휴대폰에서 음악 앱으로 듣는 경우).
- 시계는 YouTube 플레이어와 같은 인터페이스(`time`, `play`, `pause`, `seek`, `setRate`)를 가진 `PlaybackClock` 래퍼다. 연습 화면과 보정 도구는 플레이어 대신 이 시계를 쓴다.
- 맞추는 방법: 외부에서 재생 중인 곡의 어떤 가사 줄이 시작되는 순간 그 줄을 누르면 시계가 그 줄의 영상 시간으로 맞춰지고 진행한다. ±0.5초 버튼과 일시정지로 미세 보정한다.
- **임베드 우회(다른 업로드 찾기)를 하지 않는 이유:** 팬 업로드까지 막혀 있어 대체 영상을 찾는 비용이 크고, 찾아도 언제 막힐지 모른다. 외부 재생은 음원 출처와 무관하게 동작한다.
- **한계:** 사람이 누르는 시점에 따라 0.1~0.3초 오차가 생길 수 있다. 0.2초 오차 요건은 임베드 재생 곡에만 적용한다.

## Risks / Trade-offs

- [YouTube 공식 음원 중 일부는 외부 임베드가 막혀 있다] → 2026-11-10 확인 결과, 오랄과 알렉산드로스는 공식 음원·MV·팬 업로드까지 모두 오류 150이었다(레이블이 콘텐츠 ID로 막는 것으로 보임). oEmbed 확인은 통과하므로 실제 재생으로만 판별된다. 대응은 결정 9의 외부 재생 모드다.
- [LRCLIB에 가사가 없거나 틀린 곡이 있다. 특히 2026년 신곡(往欄印, CLAN QUEEN 곡 등)] → 가사는 가사 사이트에서 직접 넣고, 줄 시간은 보정 도구로 전부 찍는다.
- [스튜디오 음원과 라이브 편곡이 달라 콜 위치가 어긋난다] → 연습 기준은 스튜디오 음원으로 정하고, 라이브 전용 구간은 메모(`note`)와 공연 의식 항목으로 안내한다.
- [응원 정보 일부가 2차 출처다. oshikatsu.co.jp, Yahoo!知恵袋 등] → 공식 콜 영상이 있는 곡은 영상과 대조한 뒤 넣는다. 곡 화면에 출처 링크를 보여준다.
- [56곡 콘텐츠를 일주일 안에 만들고 검수하기 빠듯하다] → 출연일 순서(금→토→일)로 만든다. 콘텐츠가 완성된 곡부터 배포하고, 검수 상태는 곡 화면에 표시한다.
- [getCurrentTime 갱신 간격 때문에 강조가 늦거나 튈 수 있다] → 보간으로 보완한다. 일시정지, 탐색, 속도 변경 이벤트가 오면 기준값을 다시 잡는다.
- [가사가 공개 URL에 올라간다] → 사용자가 감수하기로 했다. 검색 노출을 줄이도록 `<meta name="robots" content="noindex">`를 넣는다.
- [검색 한도 때문에 약 28곡을 아직 조사하지 못했다] → 재조사를 별도 작업으로 두고, 구현과 동시에 진행한다.
